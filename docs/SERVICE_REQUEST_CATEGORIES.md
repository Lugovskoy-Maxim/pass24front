# Категории сервисных обращений

Изменения относятся к кабинету Pass и Android-приложению. Основной сайт mstyle.ru не требует изменения в рамках этой задачи.

## Временное скрытие обращений

В «Базовые настройки → Доступ арендаторов» добавлена настройка «Скрыть обращения у арендаторов». Она включена по умолчанию: `tenantServiceRequestsEnabled` отсутствует или равен `false`. Чтобы открыть раздел после доработки, администратор снимает флажок и сохраняет настройки.

В Pass скрываются пункты навигации и заказ услуг из профиля; прямая ссылка показывает недоступность раздела без загрузки обращений. Новый Android-клиент получает доступ из `tenant_service_requests_enabled` в ответе о пользователе. Сервер проверяет настройку при просмотре, создании, ответах и работе с вложениями для резидентов, включая старые клиенты и приватный API. Работа администраторов с существующими заявками сохраняется. Бронирование переговорных и заказ пропусков не зависят от этой настройки.

## Шапка и профиль арендатора

Шапка показывает компактную ссылку «Офисы: N» при нескольких назначениях; полный список доступен в профиле. Имя и компания ограничены по ширине, полное значение доступно в подсказке. На средних экранах навигация переходит на отдельную строку. Более двух предупреждений об оплате собраны в сворачиваемый список с ограниченной высотой.

Поле «Лимит сотрудников» убрано из формы профиля. Клиент не передаёт лимит при изменении данных, сервер сохраняет значение, назначенное администратором. Управление лимитом в админке и проверка количества сотрудников сохраняются.

В обоих клиентах категории идут в одном порядке:

| Ключ API   | Название    |
| ---------- | ----------- |
| `service`  | Сервис      |
| `it`       | IT          |
| `passes`   | Пропуска    |
| `services` | Доп. услуги |
| `other`    | Другое      |

Старые ключи принимаются сервером для совместимости с ранее выпущенными приложениями. `office`, `engineering`, `plumbing`, `cleaning`, `security` относятся к «Сервису»; `access`, `guest_pass`, `parking` — к «Пропускам»; `payment`, `booking`, `resident_data` — к «Другому». Старые документы не переписываются: категории нормализуются при выдаче и учитываются в фильтрах администратора.

## Прайс

При выборе «Доп. услуг» появляется отдельная кнопка «Прайс на услуги». Прайс берётся из существующих опубликованных услуг выбранного офиса, которыми управляет администратор в разделе «Прайс и категории». Позиция отображается, если она видима, доступна, имеет название и заданную неотрицательную цену. Нулевая цена считается заполненной. Показываются название, цена и единица услуги.

При отсутствии позиций показывается пустой список с сообщением «Прайс пока не заполнен». Просмотр прайса не добавляет услугу в заявку и не создаёт заказ. Отдельное действие заказа услуги использует категорию `services`.

Pass загружает прайс при раскрытии кнопки и смене офиса. Приложение использует опубликованные услуги назначенного офиса из синхронизированных данных пользователя.

## Телефон для пропуска

В Android-форме заказа пропуска телефон необязателен. Пустой номер не передаётся в API. Имя посетителя, офис, дата и корректное время по-прежнему обязательны; остальные формы и проверки телефона не изменены.

## Проверка

Проверены серверные правила категорий, старые ключи и фильтрация обращений в интеграционном тесте с временной базой MongoDB. В браузере с тестовыми данными проверены порядок категорий, появление кнопки только для «Доп. услуг», название и цена, нулевая цена, скрытые и незаполненные позиции, смена офиса, пустой прайс и категория в запросе создания обращения. Проверен экран шириной 390 пикселей.

В Android добавлены проверки порядка категорий и старых ключей, отображения опубликованных цен и валидности пропуска без телефона. Выполнены модульные тесты и сборка debug APK. Проверка на физическом устройстве и выпуск приложения в магазин не выполнялись.

Проверены сохранение, включение и отключение доступа в админке, скрытый прямой маршрут и отсутствие заказа услуг. Шапка с 24 офисами и длинными именем и компанией проверена на ширинах от 320 до 1440 пикселей, а также с 24 неоплаченными офисами. Серверный тест проверяет блокировку заявок, ответов и вложений при скрытии и возможность продолжать обработку администратором; отдельный тест — сохранение назначенного лимита сотрудников.
